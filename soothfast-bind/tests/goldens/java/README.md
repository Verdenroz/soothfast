# acme.core

Java bindings for the `acme` crate, generated by [soothfast](https://github.com/Verdenroz/soothfast). Do not edit by hand: run `cargo soothfast bind gen` instead.

## Build

```bash
cargo build --release
```

That writes `target/release/libacme_core.so` (`.dylib` on macOS, `acme_core.dll` on Windows). Compile the Java sources against it and put the library on the loader's path:

```bash
javac -d out $(find src/main/java -name '*.java')
jar --create --file acme_core.jar -C out .
java -Djava.library.path=target/release -cp acme_core.jar YourMain
```

## Use

```java
import acme.core.Core;
```

Every handle class implements `AutoCloseable`; call `close()` (or use try-with-resources) to free it deterministically. A `java.lang.ref.Cleaner` frees one you forgot, but not on any schedule you should rely on.

A borrowed buffer parameter (`double[]`, `byte[]`, ...) is read through `GetPrimitiveArrayCritical`: it crosses without a copy, but the garbage collector cannot run for the length of that one call.

## Not bound

- acme::Counter::consume: takes `self` by value, which would empty the handle the binding holds; take `&self` and return a new value instead
- acme::with_time: foreign type `chrono::DateTime` has no mapping; add one under [bind.types] in soothfast.toml
- acme::Counter::refresh: `async fn` cannot cross into java: no Java runtime story yet
- acme::index_all: `HashMap<String, u32>` cannot cross into java: C has no map type; return a sequence of pairs, or an exported type with accessors
- acme::merge: crosses the exported type `Counter` by value, which would copy it; take it by reference, or add a method returning what the caller needs
- acme::trim: `Option<Vec<f64>>` cannot cross into java: `Option<Vec<f64>>` has no C spelling; only an optional exported type does, as a pointer that may be null
