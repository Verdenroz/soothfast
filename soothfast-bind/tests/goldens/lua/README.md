# core

C bindings for the `acme` crate, generated by [soothfast](https://github.com/Verdenroz/soothfast). Do not edit by hand: run `cargo soothfast bind gen` instead.

## Build

```bash
cargo build --release
```

That writes `target/release/libcore.so` (`.dylib` on macOS, `.dll` on Windows) and `target/release/libcore.a`. The header is `core.h`.

## Use

```c
#include "core.h"
```

## Ownership

Anything this library returns by pointer is yours to release:

- a handle, with its `*_free`
- a sequence, with its `*_array_free`
- a string, with `core_string_free`

A call that can fail takes a trailing `char **error`. On failure it writes a message there and returns a zero value you must not read; on success it writes `NULL`. Passing `NULL` for `error` discards the message. Every message is a string you release the same way.

## Not bound

- acme::Counter::consume: takes `self` by value, which would empty the handle the binding holds; take `&self` and return a new value instead
- acme::with_time: foreign type `chrono::DateTime` has no mapping; add one under [bind.types] in soothfast.toml
- acme::Counter::refresh: `async fn` cannot cross into lua: no Lua runtime story yet
- acme::index_all: `HashMap<String, u32>` cannot cross into lua: C has no map type; return a sequence of pairs, or an exported type with accessors
- acme::maybe_ratio: `Option<f64>` cannot cross into lua: `Option<f64>` has no C spelling; only an optional exported type or string does, as a pointer that may be null
- acme::merge: crosses the exported type `Counter` by value, which would copy it; take it by reference, or add a method returning what the caller needs
- acme::trim: `Option<Vec<f64>>` cannot cross into lua: `Option<Vec<f64>>` has no C spelling; only an optional exported type or string does, as a pointer that may be null

## Lua

This package also ships a LuaJIT module generated over the same header and library. `require` it once the shared library the C backend built is reachable through `ffi.load("core")`'s search (set `LD_LIBRARY_PATH`, or place it somewhere the platform's loader already looks).

A plain Lua table crossing a buffer parameter is copied element by element, boxed number by boxed number. A caller already holding a matching FFI array, built with `ffi.new("<ctype>[?]", n)`, passes it through with no copy instead.
